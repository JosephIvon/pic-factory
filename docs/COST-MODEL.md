## 3. 一笔账 + 关键裁决（诚实标注"为什么故意不改代码"）

月发布 5000 篇图文，复用 3:1 → 需生成 ≈1700 张：
- 全旗舰 API：1700×0.2 = **¥340**〔单价实测、张数为工作假设〕
- L2 分档（20% 旗舰+80% 低价 0.1）：≈1700×0.12 = **¥204**〔低价档真实感未验证〕
- L1+L2+L4（复用+分档+本地长尾）：**≈¥120 或更低**〔自建吞吐为估算〕

**分水岭**：月产 <1 万张 → 自建省的是几十块、赔的是运维人力，不值；**>5 万张/月** 自建才压倒性。

本项目**故意没做**的两件事（不是遗漏，是纪律）：
1. **没把 GLM-Image / 火山通用 0.1 档塞进 `models_spec` 路由**——它们的 **endpoint/model_id 我未验证、真实感我未实测**。
   塞进去=拿未验证模型出成品，违反"不编数"。已在本文列为**待 A/B 候选**，跑过真实感盲测再入表。
2. **纯场景没从 Seedream 4.0(¥0.20) 降到 5.0-Flash(¥0.10)**——省 ¥0.10，但盲测真实感 4.0 是 0/4、Flash 1/4，
   医美对真实感敏感，**不为省一毛钱牺牲真实感**。这条留在 `model_choice` 注释里，等有实测低价档再动。

## 4. L1 复用率是本项目的下一个真缺口

现状：`tasks.yaml` 每条(城市×项目×主题)都当独立生成任务 → 生成量≈发布量，没吃到最大杠杆。
落地建议（整合后 v2）：任务矩阵拆两层——**素材生成层**（少量旗舰出底图/角色卡）与**内容组装层**
（底图 × 文案 × 城市名 用 LLM+Pillow 叠字裂变，零额外生图费）。这是"发布 5000 只生成 1700"的机制来源，
也是把本项目从"调用级"抬到"工业化"的决定性一步。

## 5. 一句话结论

> "生图按张看着比 NLP 包月贵，但我算的是**每篇发布内容的有效成本**，不是每张图。
> 复用率把生成量压到发布量的三分之一，分档把均价从 2 毛压到 1 毛，自建推理吃长尾、
> 预算熔断防返工——真到月产五万张以上才值得全自建，这个阈值我算过。
> 包月（MJ relax）最便宜但没有官方 API、条款风险，进不了'系统自动调用'的管线，所以我没选它。"

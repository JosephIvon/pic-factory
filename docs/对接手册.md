## 1. 系统定位

**医美行业的图文批量生产流水线**：按「城市 × 项目 × 主题 × 渠道 × 角色」展开任务矩阵，
逐条任务自动路由到生成后端，过质检闸门与合规闸门，产出可直接交付的发布包。
每张图的判定、耗时、成本与路由理由全部落台账，可逐条追溯。

行业知识不进代码：接一个生图模型 = 在模型注册表加一行；换一个行业 = 写一份域包（5 份 YAML）。

三条贯穿全部行为的设计决策：

1. **闸门 fail-closed**。闸门没执行 ≠ 合格：OCR 引擎或人脸模型不可用时，相关任务一律
   拒收而不是跳过；拒收理由逐条写在台账 `qc_reasons` 字段里，可逐条查证。
2. **台账是唯一事实源**。单文件 SQLite：判定、成本、路由规则、模型档位、人工采纳全在其中。
   改单价不需要重新生成图片，重跑 `report` 即刷新成本账。
3. **不编造数字**。单价没配置就只显示调用次数与实测秒数，不出金额；关键参数（如人脸阈值）
   有证据文件可查，来源见 §3.2。

## 2. 架构

```
行业域包（domain pack，5 份 YAML；AP_PACK 指向甲方目录，不进本仓库）
      │  任务矩阵展开 + 幂等键 + 提示词编译
      │  编译期不变量：原始中文标签不得进入画面 prompt（违反直接报错）
      ▼
路由（两个正交维度，决策理由落台账）
      · 后端规则表：R0 全局不出网 → R1 任务不出网 → R2 需中文排版 →
        R3 强身份 → R4 铺量（优先级：合规 > 排版 > 一致性 > 成本）
      · 模型档位：M1~M3（任务类型 > 一致性下限 > 成本）
      ▼
生成（provider 层，一个 generate() 契约，多后端）
      http_api  标准 HTTP API（交付路径，计费断言 billed==1）  ｜  matrix  外部连接器（参照，不可交付）
      local     本地扩散模型栈（数据不出网）  ｜  replay  离线回放 fixtures/（不出网、不花钱）
      成本闸：RPM 令牌桶限流 + 预算熔断（80%）+ 预扣/退还原子化
      ▼
质检（fail-closed：闸门没跑 ≠ 合格）
      ① 硬规则（必拦）：画面内文字 OCR / 短边分辨率下限 / dhash 近似重复
      ② 人脸闸（数值闸）：身份一致性 T=0.57（同域样本标定）
      ③ 出厂判定：换脸兜底后，在最终产物上复检硬规则 + 人脸闸
      ④ 合规闸：禁用词 + 免责声明 + AI 标识 + 图文成对
      ▼
交付与记账
      人工采纳（点「用/不用」）→ 发布包 zip（manifest 含 AI 生成标识）→ 发布/效果人工回填 → 漏斗报表
      SQLite 台账（WAL 模式）：每张图一行，全字段留证
      Web 面板：读走台账、写走 CLI 子进程（流水线逻辑只有一份）
```

## 3. 规格表

### 3.1 命令面（`aesthetics <命令>`，以 `cli.py` 实际注册为准，共 20 个）

| 命令 | 作用 | 花钱 |
|---|---|---|
| `plan` | 展开任务矩阵并预览每条任务的路由决策与命中规则 | 否 |
| `generate` | 批量生成：编译提示词 → 路由定后端 → 生成 → 记台账（幂等跳过、失败精确重试） | 视后端 |
| `qc` | 批量质检：硬规则 + 人脸闸，判定放行/拦截并落台账 | 否 |
| `qc-file <图片>` | 对任意单张图跑硬规则，退出码 1 即拦截（不经过台账） | 否 |
| `faceswap` | 换脸兜底 + 出厂复检（只处理已质检放行的图生图产出） | 否 |
| `copy` | 按规则模板生成文案并过禁用词闸 | 否 |
| `compliance` | 合规审计（免责声明/图文成对/画面文字/禁用词），不过则退出码 1 | 否 |
| `publish` | 打发布包 zip（默认 fail-closed，只打包已采纳素材） | 否 |
| `adopt <key>` | 人工采纳：点「用/不用」，可带备注 | 否 |
| `adoption` | 采纳率报表（adopted/generated，按后端分组） | 否 |
| `publish-record <key>` | 登记一次发布（渠道、链接），回填台账 | 否 |
| `metrics <key>` | 登记效果数据（曝光/点击/收藏/评论/分享） | 否 |
| `funnel` | 漏斗：产出 → 放行 → 人工采纳 → 已发布 → 有回传数据 | 否 |
| `library` | 复用素材盘点（按角色×项目×主题汇总可复用/已采纳资产） | 否 |
| `report` | 拼图 + CSV + JSON + 合规审计 + 后端成本对比 + 采纳率 | 否 |
| `calibrate-face` | 身份相似度分布自检（不是标定；生产阈值标定证据见 §3.2） | 否 |
| `compare` | 后端可用性预检（跑对比实验前确认两个后端就绪） | 否 |
| `packs` | 列出可用域包并标出当前生效包 | 否 |
| `panel` | 起 Web 面板（任务提交 + 画廊 + 每张明细），默认 `127.0.0.1:8000` | 否 |
| `reset-db` | 清空台账（`--confirm` 才执行；不动素材与缓存） | 否 |

### 3.2 质检链

| 环节 | 口径 | 依据 |
|---|---|---|
| 硬规则（必拦） | 画面内检出文字即拒（医美内容翻车点）；短边 < 512px 拒；与已有产出 dhash 距离 ≤ 6 判近似重复拒；图片无法解码拒 | `qc/rules.py` |
| 中文标签防线 | 原始中文标签只在文案层；编译期校验画面 prompt 无中文标签，违反直接报错 | `router.py` |
| 人脸闸 | 数值闸，阈值 **T=0.57**：同域正样本 45 张（其中无遮挡合格样本最低 0.6406）与同域难负 7 张（最高 0.4918）取间隙中点；可用 `AP_FACE_THRESHOLD` 覆盖 | 证据文件 `docs/ab-evidence/threshold-calibration-production.json` |
| fail-closed | 文字闸/人脸闸**没执行＝不能记为合格**：OCR 引擎或人脸模型不可用时相关任务拒收，理由写入 `qc_reasons` | `qc/rules.py` / `qc/face.py` |
| 生成阶段人脸分 | 低于阈值只标记「漂移」，不拦截（中间产物拦截会误杀）；出厂判定放在换脸之后 | `cli.py` qc 段 |
| 出厂判定 | `faceswap` 换脸后，对**最终产物**重跑硬规则 + 人脸闸，任一不过即拒收 | `cli.py` faceswap 段 |
| 禁用词 | 文案生成时统计命中；合规审计复核 | `copy.py` / `compliance.py` |

### 3.3 合规与出网

| 机制 | 行为 |
|---|---|
| 全局不出网开关 | `generate --no-cloud`：全部任务走本地栈，优先级高于整张规则表（规则 `R0_NO_CLOUD_GLOBAL`） |
| 任务级不出网 | 域包里项目/主题标记 `no_cloud`，命中规则 `R1_NO_CLOUD`，同样只走本地栈 |
| 冲突拒跑 | 手动指定云端后端（`--provider http_api` 或 `matrix`）且存在不出网约束时，**起跑前直接拒绝**（退出码 1），一张图都不发；不接受命令行静默覆盖合规约束 |
| 不回退云端 | 不出网任务在本地栈不可用时明确报错退出，**拒绝回退到云端**（合规优先于可用性） |
| AI 生成标识 | 发布包 `manifest.json` 每条记录含 `ai_label`（显式标识=平台水印，隐式标识=元数据，默认开），即《AI 生成合成内容标识办法》的隐式标识落点 |
| 发布包 fail-closed | 合规审计不过默认拒绝打包（缺免责声明、图文不成对都是阻断项）；确要强打需显式 `--allow-violations`，且会如实写进包内 `compliance.json` |

### 3.4 成本

| 机制 | 口径 |
|---|---|
| 逐张记账 | 每笔产出落台账 `est_cost`：API 后端按所选模型档位的单价，本地栈按「电费 + 设备折旧」公式由实测秒数现算 |
| 预算熔断 | `AP_BUDGET_CNY` 设预算帽，累计花费达 **80%** 停发新调用（跨批次累计，从台账播种；设计行为，留 20% 余量收尾） |
| 不花钱路径 | `replay` 离线回放读随仓库夹具，不出网不花钱；`generate --reuse-adopted` 命中已采纳素材时本地复制顶上，`est_cost=0` 落台账 |
| 不编造金额 | 单价环境变量未配置时，报表只出调用次数与实测秒数，成本列显示「未配置单价」 |
| 成本口径 | 报表按「单张合格图综合成本 = 总花费 ÷ 合格张数」对比后端，拒收的张数也计入分母成本 |

### 3.5 工程与台账

| 机制 | 行为 |
|---|---|
| SQLite | WAL 模式 + `busy_timeout=5000ms`；面板与 CLI 并发写已缓解（见 §6 排错） |
| 台账主键 | `(idempotency_key, provider, variant)`：同一任务的多个后端、多个模型档位产出并存，互不覆盖 |
| 幂等跳过 | API 后端按「后端 + 模型档位」精确匹配：同档重跑跳过，换档重新生成并计费（新档是新的一行资产） |
| 面板任务落库 | 提交的批次写台账；服务重启时把残留的 `running` 标记为 `interrupted`，不会把提交闸永久锁死 |
| 面板提交闸 | 一次只允许一个批次在跑（并发提交返回 409），防止双份花钱 |
| 面板鉴权 | 非回环地址绑定必须设 `AP_PANEL_TOKEN`，否则拒绝启动（fail-closed）；凭据支持 `Authorization: Bearer`、`?token=`、cookie 三种；token 比较为定长 UTF-8 编码比较，非法凭据返回 401 |
| 面板实现 | 读走进程内台账查询，写走 CLI 子进程；静态页零 CDN 依赖，断网可开 |

## 4. 端到端走一遍

**环境**：Python 3.11+，先装依赖。核心链路只需 `pip install -e .`；`[qc]` 才有 OCR 与人脸闸，
`[panel]` 才有 Web 面板；交付镜像已装 `.[qc,panel]`。`<尖括号>` 为占位符，按实际值替换。

**第 0 步 · 看一眼会产出什么（不花钱）**

```bash
aesthetics packs                          # 域包是否加载成功
AP_PACK=<包名> aesthetics plan --limit 5   # 任务矩阵 + 每条路由决策与理由
```

预期：一张表，每行有后端与 `rule_id`；结尾打印「提示词通过中文标签不变量校验」。

**第 1 步 · 离线回放全链路（不花钱、不出网）**

```bash
aesthetics generate --provider replay --replay-provider matrix --db /tmp/demo.db --limit 4
aesthetics qc --db /tmp/demo.db
aesthetics report --db /tmp/demo.db
```

预期：`generate` 4/4 成功；`qc` 每条给出判定与理由；`report` 出拼图 + CSV + JSON。

> 注意：matrix 夹具 4 条**全是人物任务**。没装 `[qc]` extra 时 `qc` 会把这 4 条**全部拒收**，
> 理由是「人脸模型不可用：人脸闸未执行，不能记为合格」。这是闸门在正常工作，不是故障；
> 装上 `[qc]`（含人脸权重）才能看到放行。

**第 2 步 · 真实生成（花钱）**

```bash
export AP_ARK_KEY=<火山方舟 API Key>        # 或 AP_DASHSCOPE_KEY=<阿里百炼 API Key>
export AP_BUDGET_CNY=200                   # 预算帽：累计花费达 80% 停发新调用
export AP_COST_API=0.20                    # 单价口径；不配则只出次数与秒数
aesthetics generate --provider auto --limit 6
```

预期：自动路由分流，台账每行有 `route_rule_id` 与 `est_cost`。
要求全程不出网时加 `--no-cloud`（此时必须保证本地栈可用，否则拒绝起跑）。

**第 3 步 · 质检 → 换脸 → 出厂复检**

```bash
aesthetics qc
aesthetics faceswap
```

- `qc`：OCR 拦画面内文字；人物任务画面无人脸 → 拒收；人脸闸不可用 → 拒收。
- `faceswap`：只处理已质检放行的图生图产出；发现未质检的图生图产出会**直接报错退出**
  （不做部分处理）；换脸后的最终产物再跑硬规则 + 人脸闸，任一不过即拒收。

**第 4 步 · 文案 → 合规 → 发布包**

```bash
aesthetics copy
aesthetics compliance                      # 退出码非 0 即不通过
aesthetics publish --out out/publish/demo.zip
```

预期：发布包四件套 `images/` + `copy/` + `manifest.json`（含 AI 标识）+ `compliance.json`；
缺免责声明或图文不成对的包默认打不出来。

**第 5 步 · 人工采纳与发布回填（这几步是人点的）**

```bash
aesthetics adopt <idempotency_key> --decision adopted --note "<备注>"
aesthetics adoption                        # 采纳率，按后端分组
aesthetics publish-record <idempotency_key> --channel <渠道> --url <发布链接>
aesthetics metrics <idempotency_key> --impressions 1200 --clicks 36
aesthetics funnel                          # 产出 → 放行 → 采纳 → 已发布 → 有数据
```

## 6. 故障排查

| 症状 | 大概率原因 | 处置 |
|---|---|---|
| `ModuleNotFoundError: insightface` | 只装了核心依赖 | `pip install -e ".[qc]"`；离线环境须预置 buffalo_l 权重到 `AP_INSIGHTFACE_ROOT` |
| 人物任务全部拒收，理由「人脸闸未执行」 | 人脸模型不可用（fail-closed，非故障） | 装 `[qc]` extra 后 `aesthetics qc --reset` 重跑 |
| 全部拒收，理由「OCR 引擎不可用」 | 缺 `rapidocr-onnxruntime`；Linux 裸容器另缺 `libgl1` | 装依赖；容器内 `apt-get install -y --no-install-recommends libgl1 libglib2.0-0` |
| `faceswap` 报「还有 N 条没质检」 | 有图生图产出未跑 `qc` | 先 `qc` 再 `faceswap`；不部分处理是刻意的 |
| `faceswap` 退出码 1，提示换脸模型不可用 | `inswapper_128.onnx` 不在环境 | 按代码内说明放置模型；商用前必须替换授权模型（见 §7） |
| 批次中途「预算熔断」 | 累计花费达 `AP_BUDGET_CNY` 的 80% | 设计行为；提预算或改走 `replay`；台账有每笔 `est_cost` |
| `database is locked` | 台账放网络盘，或被长事务占锁 | WAL 与 5 秒等待已内建；把台账放本地盘、避免多机共库 |
| 面板返回 401 | 未带凭据或凭据错误 | 浏览器用 `/?token=<AP_PANEL_TOKEN>` 打开一次（写 cookie）；脚本用 `Authorization: Bearer`；含中文/特殊字符的 token 也支持（服务端按 UTF-8 编码做定长比较；历史版本此类请求会 500，已修复） |
| 面板起不来或报缺依赖 | 面板依赖未装，或非回环绑定未设 token | `pip install -e ".[panel]"`；绑非回环必须设 `AP_PANEL_TOKEN`（CLI 主链路不受面板影响） |

## 7. 已知边界（对接前必须知道）

如实列出限制，是这份文档可信度的基础。

**能力边界**

- 只做图文，不含视频 / 音频 / 3D。
- 不做自动发布：到「发布包 zip」为止；发布动作与效果数据由对方系统承接，
  用 `publish-record` / `metrics` 人工回填后 `funnel` 出漏斗。
- 无账号体系与多租户：面板单实例、单共享 token；不区分操作人。
- 文案是规则模板（固定占位符），接 LLM 生成属后续开发。
- 画面内中文排版无自动合成：中文标签被挡在画面 prompt 之外，成品需要压字时需另行后处理。
- VLM 只做软信号，不参与拦截（实测存在漏检）；硬判定全走 OCR 与人脸闸。

**工程边界**

- 单机 SQLite：WAL 与等待重试已内建，但无作业队列、长批次无断点续跑；单进程线程池并发，
  高吞吐与多机水平扩展（多实例共库/共存储）需另做队列与存储；台账不建议放网络文件系统。
- 幂等键由任务维度（城市×项目×主题×渠道×角色）派生，不含提示词模板版本：
  改提示词模板后重跑，需 `--no-skip-existing` 强制重出（API 后端换模型档位不受此限，见 §3.5）。
- 离线回放夹具只覆盖 matrix / local 两条路线（http_api 无夹具）；夹具为压缩副本，
  身份分会随压缩轻微漂移，要精确复现请实跑。
- 换脸模型 `inswapper_128.onnx` 为非商用研究许可，商用交付前必须替换为授权模型。

**口径边界（容易被追问，先说清）**

- 人脸阈值 T=0.57 是同域样本标定值（正样本 45 张、同域难负 7 张）。
  **n=7 的误放率没有统计意义**：这个阈值只当工程红线用，不当合规证据；
  扩到 ≥150 负样本的复核尚未做。
- 模型选型用的一致性数字是单次观测（每模型 10 张、一轮），只用于「排除」、不用于排名；
  唯一真源是 `docs/ab-evidence/model-sim-recompute.json`。
- 成本单价（API 报价、功耗、电价、折旧）均为工作假设，需以对方实际报价替换后再作数。

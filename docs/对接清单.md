# 对接清单 · 双方备料与验收口径

> 对象：拟接入 pic-factory 图文生产线的合作方对接负责人
> 版本：v3 · 2026-10-24 · 开源版（MIT）
> 分工：《对接手册》管「怎么安装、怎么跑命令」；本清单管「合作启动前备什么料、我方交付什么、按什么口径验收」。
> 两份一同使用：本清单逐项确认后，按《对接手册》的端到端步骤做验证。

---

## 0. 使用方式与合作边界

- 阅读顺序：§1 甲方逐项备料 → §2 我方交付 → §3 验收单逐项勾选 → §4 按里程碑推进。
- 优先级口径：**阻断级** = 缺一项无法启动；**重要** = 能跑但要返工；**加分** = 提高成色。
- 已知能力边界（先对齐期望，避免后期争议）：
  - 只做图文，不含视频 / 音频 / 3D；
  - 不做自动发布：交付到「发布包 zip」为止，上传动作由甲方系统或人工承接；
  - 单机单实例：面板默认回环访问，SQLite 存储，不做账号体系与多租户。

## 1. 甲方需提供（备料清单）

### 1.1 业务规格（阻断级）

系统按「城市 × 项目 × 主题 × 渠道 × 角色」展开任务矩阵，各维度取值全集由甲方给出：

| # | 事项 | 形式 | 验收口径 |
|---|---|---|---|
| A-1 | 城市清单 | 列表 / CSV | `aesthetics plan` 展开条数与甲方确认数一致 |
| A-2 | 项目/品类清单 | 每项含名称 + 是否需要真人出镜 | 任务矩阵展开无缺项 |
| A-3 | 每个项目的出网约束 | 布尔（`no_cloud`） | `aesthetics plan` 中命中 `R1_NO_CLOUD` 的条目与约束清单一致 |
| A-4 | 主题/内容角度库 | 每项含名称 + 是否需要中文排版（`needs_text_overlay`） | 命中 `R2_TEXT_OVERLAY` 的条目正确 |
| A-5 | 首期规模与节奏 | 目标条数 + 出图节奏 | 决定并发与预算配置（见 1.4） |

> 首期建议单城市控制在 50 条以内；矩阵条数随维度乘积增长，先小后大。

### 1.2 品牌素材与合规口径（阻断级 · 最高优先级）

医美内容受《广告法》《医疗广告管理办法》《AI 生成合成内容标识办法》约束。
这一节不齐，系统能跑但产出不可发布。

| # | 事项 | 形式 | 验收口径 |
|---|---|---|---|
| B-1 | 禁用词表（甲方口径，可覆盖内置默认） | YAML 列表，每条含词 + 归类 | `AP_PACK=<包> aesthetics compliance` 退出码 0 |
| B-2 | 强制免责声明（逐字进每条文案） | 一段固定文本 | 缺免责声明的发布包打不出来（fail-closed） |
| B-3 | AI 生成标识要求 | 水印文案 + 位置说明 | 发布包 `manifest.json` 含 `ai_label` 段 |
| B-4 | 禁用构图/画面红线 | 清单 | 进人工复核清单（当前不做自动判定，需确认接受人工兜底） |
| B-5 | 机构/资质表述口径 | 正面 + 负面清单 | 与 B-1 合并同一份词表 |
| B-6 | 法务确认 | 书面确认词表与免责声明文本 | 作为交付前置条件，不在上线前补 |

> 内置默认词表按法规原文整理，是工作假设而非法律意见，以甲方确认版为准。

### 1.3 视觉资产与肖像授权（阻断级）

先交资产，再谈授权：

| # | 资产 | 规格 | 去向 |
|---|---|---|---|
| C-1 | 角色卡 | 每个角色：冻结的英文身份描述（`identity_block`）+ 定妆照路径（`ref`） | 进域包 `characters` 段 |
| C-2 | 定妆照/参考图 | 高分辨率正脸单人照 | 图生图路线的身份一致性基准 |
| C-3 | 场景参考图（可选） | 诊室/门店实拍 2–3 张，不含可识别患者信息 | 进场景画面描述 |
| C-4 | 品牌视觉规范 | 主色、辅助色、禁用视觉元素 | 进拼图与文案后处理，不进生成链路 |
| C-5 | 画幅与分辨率基线 | 每渠道画幅比例 + 分辨率 | 进域包 `channels` 配置 |

授权是发布红线。每个进入发布链路的角色，都要在域包 `assets/licenses.yaml` 登记一条授权记录，字段即验收口径：

| 字段 | 要求 | 示例（需甲方确认/替换） |
|---|---|---|
| `kind` | `synthetic`（AI 生成虚拟人）或 `real`（真人） | `synthetic` |
| `source` | 素材来源说明 | 「AI 生成定妆照，非真人模特」 |
| `license` | 授权范围 | 「自有虚拟人设，可商用」 |
| `commercial_use` | 可否商用 | `true`；为 `false` 的角色发布包会被拦下 |
| `consent` | 肖像同意情况（真人为必填） | 真人需附授权书、授权期限与撤回机制 |
| `valid_until` | 授权期限 | `null` = 长期有效；填日期则到期后检查失败 |

配套要交：每个角色一张定妆照/参考图（高分辨率正脸单人照）；品牌视觉规范（主色、禁用视觉元素）。
红线：**没有授权记录的角色不得进入发布包**，`aesthetics publish` 按此拦截。

### 1.4 算力与密钥（阻断级，二选一）

| # | 档位 | 甲方提供 | 说明 |
|---|---|---|---|
| E-1 | 云端 | 生图 API 密钥（火山方舟或阿里百炼任一）+ 单日限额 | 密钥以环境变量注入（`AP_ARK_KEY` / `AP_DASHSCOPE_KEY`），不落文档、不入库；建议子账号 + 定期轮换 |
| E-2 | 本地 | 一台 GPU 主机 + 离线权重预置 | 数据不出网；人脸闸权重必须预置，否则人物任务一律拒收（闸门 fail-closed） |

配套配置：

- 预算上限 `AP_BUDGET_CNY`：累计花费达 80% 熔断新调用；
- 单价口径 `AP_COST_API`（云端）等：不配则报表只出次数与秒数，不显示金额（仓库纪律：不编数字）。

### 1.5 渠道、采纳与验收人（重要）

| # | 事项 | 说明 |
|---|---|---|
| D-1 | 发布渠道清单 | 每渠道一个英文标识（如 xiaohongshu / wechat），登记进域包 `channels` 段；发布后以 `aesthetics publish-record` 写入回传表 |
| D-2 | 各平台图文规格与审核规则 | 画幅比例与文案长度上限进渠道配置；平台规则不等于广告法，两套都要过 |
| D-3 | 效果回传口径 | 曝光/点击/收藏/评论/分享，以 `aesthetics metrics` 回填，漏斗报表用 `aesthetics funnel` |
| D-4 | 人工采纳的角色分工 | 面板抽检台「用/不用」由谁点、是否留操作人 |
| D-5 | 双方验收人 | 姓名、角色、确认方式（邮件或签字） |

### 1.6 数据留存与安全口径（重要）

| # | 事项 | 需甲方明确 | 说明 |
|---|---|---|---|
| E-3 | 数据出网边界 | 哪些素材（提示词/参考图/产出图）允许经过云端模型 | 与 §1.1 A-3 的 `no_cloud` 标记一致；涉敏项目走本地档 |
| E-4 | 留存期限与删除 | 台账与产出图留存多久、到期如何删除 | 写入双方约定，作为验收前置口径 |
| E-5 | 二次训练禁止 | 产出物不得用于训练上游模型 | 需在约定中写明 |
| E-6 | 产出存放 | 当前落本地 `out/` 目录 | 长周期或多实例需接对象存储（加分项，另行评估） |

## 3. 双方验收口径（逐项勾选）

以下验收除预算熔断演练外全部不花钱（离线或只读），命令操作细节见《对接手册》：

- [ ] **端到端冒烟（离线回放）**：`aesthetics generate --provider replay --replay-provider matrix --limit 4` → `aesthetics qc` → `aesthetics report` 跑通；断网、无密钥环境可验。
  - 注：回放夹具为人物任务，未预置人脸权重的机器上这几条会被拒收——这是闸门正常工作，不是故障；「放行」演示需预置权重。
- [ ] **授权检查全绿**：`python tools/check_asset_licenses.py` 退出码 0（每个角色都有可商用授权记录）。
- [ ] **质检链抽检（拒收样例能被拦）**：`aesthetics qc-file <任一问题图片>` 退出码 1，拦截理由可逐条查。
- [ ] **预算熔断演练**：把 `AP_BUDGET_CNY` 调低后发起一次真实生成，确认累计花费达 80% 即不再发起新调用（需甲方密钥，单独约定窗口）。
- [ ] **面板鉴权**：面板绑定非回环地址且未设 `AP_PANEL_TOKEN` 时拒绝启动；设 token 后无凭证请求被拒。
- [ ] **合规发布闸**：`AP_PACK=<包> aesthetics compliance` 退出码 0；缺免责声明或图文不成对时 `aesthetics publish` 拒绝打包。
- [ ] **容器与回归**：`docker compose up --build` 可启动；`pytest -q` 全绿。

> 验收不通过的处置：逐项记录理由 → 修复 → 重跑该项，直至全部勾选后由双方验收人确认。

## 4. 里程碑建议（每步有可勾选的完成标准）

### M1 环境就绪

- [ ] 部署形态确定：云端密钥或本地 GPU 主机（§1.4 二选一）
- [ ] 密钥/权重注入并验证可用
- [ ] 面板可访问且鉴权通过（§3 对应项勾选）

### M2 离线验收

- [ ] 甲方按五份 YAML 填完域包（模板见 `packs/example-retail/`，契约见 `docs/DOMAIN-PACKS.md`）
- [ ] `aesthetics plan` 路由结果与甲方预期一致
- [ ] §3 的离线三项（冒烟、授权检查、质检抽检）全部勾选

### M3 小批量试产（预算内）

- [ ] 首期不超过 50 条全部生成
- [ ] 质检与合规抽检通过；拒收样本有理由记录
- [ ] 预算熔断演练完成（§3 对应项勾选）
- [ ] 实测单张成本与预算口径核对一致

### M4 抽检采纳

- [ ] 人工抽检「用/不用」流程走通，采纳记录落账
- [ ] `aesthetics publish` 打出合格发布包（只含已采纳素材）
- [ ] 甲方确认发布包可被其系统或人工流程消费

### M5 正式批量

- [ ] 规模与节奏按 §1.1 A-5 跑稳
- [ ] 回传表登记与漏斗报表可用（`aesthetics publish-record` / `metrics` / `funnel`）
- [ ] 双方验收人签署验收结论，进入常态化运行

## 5. 首次对接会建议逐条确认的问题

以下问题决定 §1 各项的优先级，建议会议当场逐条勾掉：

- [ ] 哪些项目/主题的内容绝对不能出网？（→ §1.1 A-3）
- [ ] 人物出镜要求是什么？有哪些红线构图？（→ §1.2 B-4）
- [ ] AI 生成标识的具体形式：水印文案、位置、是否还要元数据标识？（→ §1.2 B-3）
- [ ] 免责声明逐字文本由谁定、谁审？（→ §1.2 B-2 / B-6）
- [ ] 禁用词表以谁为准：仅广告法，还是叠加平台规则与机构内部词库？（→ §1.2 B-1、§1.5 D-2）
- [ ] 角色是真人还是虚构？肖像授权与留存要求？（→ §1.3）
- [ ] 谁来点「用/不用」？是否多人分工、是否留操作人？（→ §1.5 D-4）
- [ ] 发布走人工上传还是系统对接？效果数据按什么节奏回传？（→ §1.5 D-1 / D-3）
